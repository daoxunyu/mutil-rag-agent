2. 智能体编排引擎 — 技术实现

2.1 LangGraph 确定性状态机

本项目的核心编排引擎基于 LangGraph StateGraph，用有向图定义 Agent 之间的协作关系。与简单的链式调用不同，LangGraph 提供了：

  • 条件边 (Conditional Edge) — Replanner 根据 `response` 字段是否为空，三向路由到 Executor/Planner/END
  • 状态 Reducer — `past_steps` 使用 `operator.add` 累加器，每次执行自动追加而非覆盖；`tried_skills` 同理
  • 节点隔离 — 每个节点函数接收完整 State，返回部分更新 (Partial State)，由 LangGraph 合并
  • 流式输出 — `graph.astream()` 每完成一个节点就 yield 一次，支持 SSE 推送

关键代码模式 — 状态定义

# app/agents/state.py — PlanExecuteState 核心状态
class PlanExecuteState(TypedDict, total=False):
    input: str                          # 用户原始输入
    selected_skill: str                 # Skill Router 选中的 Skill
    plan: List[str]                     # 待执行步骤列表
    past_steps: Annotated[List[Tuple[str, str]], operator.add]  # 已执行步骤 (累加)
    response: str                       # 最终报告 (非空→触发END)
    iteration: int                      # 防死循环硬计数器
    tried_skills: Annotated[List[TriedSkill], operator.add]     # 失败记忆 (累加)
    pending_reroute: bool               # 是否触发 Skill 切换
    transition_history: Annotated[List[StateTransition], operator.add]  # 审计时间线

2.2 Plan-Execute-Replan 闭环 (fast 模式)

fast 模式是日常故障诊断的主链路，四个节点形成闭环：

节点输入处理逻辑输出
SkillRouter用户输入 + alert_signatureLLM 在 Skill 菜单中选一个，给理由。若有历史签名，召回对应经验注入上下文selected_skill + skill_reason
Plannerselected_skill + 用户输入基于 Skill 的 Playbook (YAML定义)，LLM 制定 4-6 步诊断计划plan: List[str]
Executorplan[0] + 历史 steps执行 plan 的第一步：调用 MCP 工具获取实际数据(CPU/内存/日志等)，结果记入 past_stepspast_steps 追加一条
Replanner所有 past_steps + plan评估进度：is_finished? → 生成报告; 继续? → 更新plan; 切Skill? → should_rerouteresponse 或 plan 或 reroute 信号

Replanner 结构化输出 (Pydantic Schema)

class Act(BaseModel):

2.4 Deep 证据图 — 多 Agent 并行取证

__DEEP_EVIDENCE__

Deep 模式处理复杂故障，通过证据驱动的并行取证提高根因分析的准确性：

  1. IncidentManager — 接收告警/手动提交，创建 incident + task，写入 Postgres
  2. CorrelationContext — 时间窗口(默认15分钟)内关联告警聚合，构建上下文
  3. EvidencePlan — 基于故障假设列表，为每个假设规划取证方向
  4. 4 Agent 并行取证 — MetricAgent(时序指标)、LogAgent(日志模式)、InfraAgent(基础设施)、RunbookAgent(SOP匹配) 同时收集证据
  5. EvidenceReducer — 汇聚证据列表，去重、冲突消解、置信度评估
  6. RCAJudge — 基于证据链进行贝叶斯式根因推理
  7. RemediationPlanner — 生成分级修复建议 (立即/短期/长期) + 回滚方案
  8. ReportAgent — 格式化 Markdown 诊断报告，触发 LLM Wiki 经验沉淀

检索逻辑：用 Child 块的 embedding 做语义匹配 → 召回 Top-K Child → 返回对应 Parent 块作为 LLM 上下文。既保证了语义检索的精确性(小粒度匹配)，又提供了足够的上下文(大窗口)。

3.2 混合检索 + RRF + Rerank 完整链路

# app/rag/retrieval.py — 混合检索核心
def hybrid_search(query: str, top_k: int = 3):
    # 1. Dense: BGE-M3 embedding → Milvus.search() → Top-30
    dense_results = milvus.search(embed(query), limit=30)

    # 2. Sparse: jieba分词 → BM25 → Top-30
    sparse_results = bm25_search(query, limit=30)

    # 3. RRF 融合: score_rrf = sum(1/(k+rank_i)) for each doc
    fused = rrf_fusion(dense_results, sparse_results,
                       weights={"dense": 0.6, "sparse": 0.4})
    # → Top-15

    # 4. Rerank: BGE-Reranker-v2-m3 Cross-Encoder
    reranked = local_reranker.rerank(
        query, fused, max_length=512, batch_size=8
    )
    # → Top-3

    return reranked[:top_k]

# app/api/v1/education.py — 教育导学 SSE
@router.post("/learn")
async def education_learn(req: EducationRequest, request: Request):
    async def event_stream():
        graph = _get_edu_graph()
        initial_state = {"input": req.query, "student_id": req.student_id, ...}

        yield {"event": "message", "data": json.dumps({
            "type": "status", "content": "🎓 6 个 Agent 协作中..."
        })}

        # astream: 每完成一个节点就 yield
        async for chunk in graph.astream(initial_state):
            node_name = list(chunk.keys())[0]
            node_output = chunk[node_name]

            yield {"event": "message", "data": json.dumps({
                "type": "agent_output",
                "agent": AGENT_LABELS[node_name],
                "content": format_output(node_output)
            })}

        yield {"event": "message", "data": json.dumps({
            "type": "done", "content": "学习方案生成完成"
        })}

    return EventSourceResponse(event_stream())

benchmark/ragas_qa_50.jsonl50 题每条: question + ground_truth + contexts。RAGAS 端到端评测。

评测指标详解

类别指标公式/说明
检索质量Recall@K|检索到的相关文档| / |所有相关文档|, K=3,5,10
MRRMean Reciprocal Rank: 第一个相关文档排名的倒数均值
NDCG@K归一化折损累计增益，考虑排序位置权重
生成质量Faithfulness生成内容是否完全基于检索到的上下文 (0-1)
Answer Relevancy答案与问题的相关程度 (0-1)
Context Precision检索到的上下文中相关信息的比例 (0-1)
Context Recallground_truth 中信息被检索到的比例 (0-1)

问题原因解决方案

DEEPSEEK_API_KEY 未配置.env 未填或格式错误编辑 .env，填写真实 API Key

Milvus 连接失败Milvus 容器未就绪等待 healthy 后再启动 API (约 90s)

容器端口冲突其他项目占用相同端口停止其他项目的 docker compose，或修改端口映射
